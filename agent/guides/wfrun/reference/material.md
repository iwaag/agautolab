# Find and store material

- `wfe projects --help` describes reading registered projects and repositories. Their maintained entry explains current capabilities, setup, cooperation and evidence.
- Repository searches see tracked files. Ignored installed assets and shared deliveries may exist elsewhere; a missing source file alone does not prove a missing capability.
- `wfe share help` describes shared areas. Use `resolve` for a supplied share path and `find` for discovery. Another machine's mount path may differ from this host's path.
- `wfe run help input` describes recording inputs; `wfe run help publish` describes publishing output folders. Shared references and hashes make the selected material identifiable.
- Keep useful findings with their sources and limits. `wfe challenge help` describes durable problems and trials shared across projects. Record a challenge when it deserves to outlive this run; it is not required for every task.
- Environment summaries have observation dates and coverage limits. Check facts that affect your decision; installation paths do not establish that a service is healthy now.

- Challenge attachments are pinned to the revision the person supplied; read that revision before comparing with the latest. `wfe challenge help` explains attachments, trial publication and revision selection. A draft is durable only after publication succeeds.
